Desk Board: overview and quick start

Last updated 2026-10-15. Folder: %USERPROFILE%\Development\DeskBoard. Address: http://127.0.0.1:4173

What it is

Desk Board is a personal dashboard that runs on this PC and opens in its own window. It keeps the things that need attention in one place:

  • tasks, with due dates, priorities and repeats
  • projects, each with a status, a next action, notes and checklists
  • things that need attention
  • documents and artifacts made in Claude
  • scripts found on this PC, including the ones Claude wrote
  • Claude chats, matched to projects
  • weekly reviews
  • a Launcher tab that starts the apps built in Claude

By default every panel shows only what was worked on in the last 7 days. Older items are one click away. Optional AI buttons can suggest what to do first, turn pasted text into tasks, and write a weekly review.

It is a small Node.js program with no installs and no cloud service. The board is stored in one file, data.json, next to the program. Nothing leaves this PC unless an AI provider is connected and an AI button is clicked.

Why it runs locally

The first version was a claude.ai artifact. Artifacts load from *.claudeusercontent.com. The network firewall (a FortiGate) inspects HTTPS to that domain and replaces its certificate, so the page stayed blank. A local program avoids that problem and can also do things a web page cannot: read project folders and Claude chat history, open folders, and start apps.

Quick start

  1. Double-click Desk Board on the desktop. It starts the server with no console window and opens the board in its own window. The first open takes a few seconds.
  2. Add a task: press N (or click the Add a task box), type it, press Enter.
  3. Click Focus on a project card to see only that project, including its checklists.
  4. Open the Launcher tab to start the apps you have built.
  5. Optional: click Connect AI to turn on the AI buttons (see the user guide).

Other ways to start it:

  • Run start.cmd in the DeskBoard folder.
  • Open http://127.0.0.1:4173 in any browser while the server is running.

Closing the window does not stop the server. It keeps running in the background and uses very little. To stop it, see setup and troubleshooting.

Desk Board: user guide

Last updated 2026-10-15. See the overview for what Desk Board is and how to start it.

The window

Across the top: the title, a Last 7 days / Everything switch, the search box, the AI buttons (once an AI is connected), and Connect AI (or the name of the connected AI). Under that are two tabs, Board and Launcher.

On the Board tab, from top to bottom: the summary strip, the week strip, the panels, and a row with the Checklists, Scripts and Claude chats panels. Each panel has a small arrow next to its title that collapses it.

Changes save as you make them. Open windows pick up changes made elsewhere within a few seconds, including changes Claude makes.

Tasks

Add a task: type in the Add a task box (shortcut N). Optional fields are due date, priority (Normal, High, Low), repeat, project, and a link or file path. Press Add or Enter.

Complete a task: click its box. Completed tasks move to Recently done at the bottom of the panel. Click the box again to reopen one.

Groups: Overdue (red), Today, Upcoming, No date. Inside a group, high priority comes first, then earliest due date.

Repeating tasks: choose Daily, Weekdays, Weekly or Monthly. When you complete one, the next copy is created automatically with the next due date, and a message offers Undo. If the task was already overdue, the next date is the first one that is today or later.

Links on tasks: a web address shows Open link. A file or folder path shows Show in folder, which opens Explorer.

Today only: the Today only button (shortcut T) shows just overdue tasks, tasks due today, and high priority tasks.

Delete: the × on a task. A message offers Undo for a few seconds.

Later tasks: with the 7-day view on, a task counts as current if it is overdue, due within the next 7 days, high priority, or was added this week. Other open tasks are folded under Show N later tasks. Nothing is deleted.

Summary strip and week strip

The tiles are filters. Overdue shows only overdue tasks. Active projects shows only active projects. Needs attention scrolls to that panel. Done, last 7 days shows a small bar chart, one bar per day.

The week strip has one button per day (today and the next six) with the number of tasks due, and an Overdue button. Click a day to filter tasks to that date. Click it again to clear.

Projects

Each project card shows its status, folder, next action, progress, and counts of chats and scripts.

  • Status menu: Active, Waiting, Blocked, Unsorted, Done. Blocked projects sort first.
  • Next action: click the line under the name and type. It saves when you leave the box.
  • Progress bar: tasks linked to the project that are done, out of all of them. Checklist progress shows as checklists 2/7.
  • Touched Nd ago: the latest of: a change to the project, a task added or finished, a chat in its folder, or a script changed in its folder.
  • Stale: an Active project not touched for more than 14 days.
  • Notes: open Notes on the card for free text. A dot shows when notes exist.
  • Open folder opens the project's folder in Explorer. VS Code opens it in VS Code. Both appear only when the project has a folder.
  • Add a project: use the form at the top of the panel. The folder is relative to your user folder (for example Development\MyProject) or a full path.

Focus mode and checklists

Click Focus on a project card (or the project's name anywhere) to focus on it. A panel appears at the top with the project's name, status, next action, counts, and its checklists. The Tasks, Projects, Scripts and Claude chats panels narrow to that project, and older items are shown too. The filter bar shows Focus: Sorto (or the project name). Click Exit focus to return.

If your latest Claude chat in a project was in the last 3 hours, the header suggests Working on Sorto? Focus.

Checklists hold steps, tests, or things to verify.

  • New checklist: give it a title and, optionally, items one per line. Lines may start with - [ ], - [x], - or 1.; the marks are understood and [x] starts the item ticked.
  • Tick an item: click its box. Click again to untick.
  • Add an item: type in the box at the bottom and press Enter. Pasting several lines adds them all.
  • Hide done: hides ticked items on that checklist so only the remaining work shows. It becomes Show done.
  • Remove an item with its ×, or the whole checklist with the × at the top right. Both offer Undo.
  • Claude can add checklists to a project too. They are marked with a Claude badge.

When no project is focused, the Checklists panel in the lower row lists the recently touched checklists from all projects.

Needs attention

Things waiting on you. Add one with a title and a severity (Normal or High). High items sort first. Resolve removes an item from the list (it is kept, marked resolved). Items always show, whatever their age. Claude adds items here when something needs your decision.

Documents and artifacts

Links to things you made in Claude or elsewhere. Add a title, a web address, and a type (Artifact, Document, Other). Links are grouped by type, newest first. The Launcher tab lists the artifacts and documents too.

Weekly reviews

Click Weekly review (needs an AI connected). The AI writes a short summary of the last 7 days from your board: what you finished, what slipped, where the time went (using chats and scripts), and suggestions for next week. Each review is saved in this panel. The newest is open; older ones are folded.

Scripts

This panel lists script files found on this PC: PowerShell, Python, batch, shell and VBScript files. It includes every script Claude wrote in a chat, even in folders it would not normally scan.

  • Each row shows the language, name, a one-line description taken from the script's first comment, its project, date and size.
  • A Claude badge marks scripts Claude wrote. Hover it to see which chat.
  • Show opens Explorer on the file. Copy path copies the full path.
  • Made by Claude shows only those. Show missing includes scripts that no longer exist on disk (for example from deleted scratch folders). Rescan scans again now; otherwise the scan repeats every 5 minutes.

Claude chats

Conversations from Claude Desktop and Claude Code on this PC, newest first, with a snippet of your last message, how long ago, and how many messages. Each chat is matched to a project by the folder it ran in.

Use the dropdown on a row to change a chat's project. Chats started with no folder show No folder until you pick one. Chats from claude.ai in a web browser are not on this PC and are not listed.

Last 7 days and Everything

The Last 7 days / Everything switch at the top controls every panel at once. In Last 7 days (the default), each panel shows what was worked on this week and folds the rest under a button such as Show 23 older scripts. Click the button to expand that one panel and click it again to fold it. Everything shows it all.

Searching or focusing a project always shows everything that matches. The arrow next to a panel title collapses the whole panel. Your choices are remembered between sessions.

Search and filters

The search box filters every panel as you type: tasks, projects, notes, checklists and their items, attention items, links, scripts, chats and reviews. Filters you set (focus, overdue, a day, active projects, today only, search) appear as chips under the header. Click the × on a chip to remove it, Clear all, or press Esc.

Launcher tab

The Launcher lists the apps you have built, each with a status and buttons.

  • Running / Stopped: shown for apps with a web address on this PC. Apps without one show No status (for example tray apps).
  • Start runs the app's start script.
  • Start and open runs it, waits until it is up (up to about 30 seconds), then opens its address in your default browser.
  • Open appears when the app is running and opens its address.
  • Show script opens Explorer on the start script. The script's output goes to launchers\logs.
  • Add an app: use the form under the list: a name, an optional description, the start script (a path relative to the DeskBoard folder, or a full path), the address, and a project.

There is no Stop button. Close an app the usual way, or see setup and troubleshooting.

Below the apps, Made in Claude lists your artifacts and documents. Add more on the Board tab.

AI buttons

Click Connect AI and pick a provider (setup steps are in setup and troubleshooting). Once it is connected, three buttons appear.

Chat titles are sent, never chat content. If the provider is Claude Desktop, requests wait for a Claude session to answer them (see using Desk Board with Claude).

Tips

  • Back up data.json now and then. It is the whole board.
  • Give each active project a next action. The AI buttons work only from what is on the board, so a next action gives them something to go on.
  • Put start scripts for anything you build in launchers\ so it shows up in the Launcher.
  • To get a list from a chat onto the board, ask Claude to add it as a checklist on the project.

Desk Board: setup, operation and troubleshooting

Last updated 2026-10-15. This is the runbook. For how to use the board, see the user guide.

Requirements

  • Windows 11 and Microsoft Edge (Edge gives the app-style window; any browser works for the address).
  • Node.js 22 or later on the PATH. Check with node --version.
  • Nothing to install for Desk Board itself. It has no dependencies.

Setting it up on a PC

  1. Get the program into %USERPROFILE%\Development\DeskBoard. Either clone the private repository (gh repo clone LCMS-Foundation/DeskBoard "$env:USERPROFILE\Development\DeskBoard"), or download the zip from the latest release, or copy the folder from another PC. Your board (data.json) and settings (config.json) are not in the repository; copy data.json across if you want the same board.
  2. Run start.cmd. The server starts and the board opens.
  3. Create the desktop shortcut (run this in PowerShell):
$dir = "$env:USERPROFILE\Development\DeskBoard"
$lnk = Join-Path ([Environment]::GetFolderPath("Desktop")) "Desk Board.lnk"
$s = (New-Object -ComObject WScript.Shell).CreateShortcut($lnk)
$s.TargetPath = "$env:WINDIR\System32\wscript.exe"
$s.Arguments = '"' + "$dir\launch.vbs" + '"'
$s.WorkingDirectory = $dir
$s.IconLocation = "$dir\deskboard.ico,0"
$s.WindowStyle = 7
$s.Save()
  1. Optional: make the server start when you sign in to Windows by double-clicking startup-install.cmd. It adds one file, DeskBoard-server.vbs, to your Startup folder (shell:startup). Double-click startup-remove.cmd to undo it.

The shortcut runs launch.vbs. That starts the server with no console window, waits until it answers (up to 15 seconds), then opens the board in an Edge app window. If Edge cannot be started it opens your default browser.

Starting, stopping and restarting

TaskHow

Stop the serverRun the command below

Stop the server:

Get-CimInstance Win32_Process -Filter "Name='node.exe'" | Where-Object { $_.CommandLine -like "*server.js*" } | ForEach-Object { Stop-Process -Id $_.ProcessId }

Closing the board window does not stop the server. If you start the server while it is already running, the second copy exits quietly and nothing changes.

When files change:

  • index.html (the page) is read on every load. Reload the window; no restart needed.
  • server.js, store.js, collector.js and mcp-server.js need a restart (and, for mcp-server.js, a new Claude session).

To use a different port, set the DESKBOARD_PORT environment variable before starting the server. The shortcut, start.cmd and launch.vbs assume 4173, so edit them too.

Connecting an AI

Click Connect AI, choose a provider, and click Save and test. Once it passes, the AI buttons appear. Disconnect removes the connection and any saved key.

ProviderWhat you needNotes
Claude Desktop (a session answers)NothingRequests wait until a Claude session in the DeskBoard folder answers them. See using Desk Board with Claude.

The API key is saved in config.json and is never sent to the page. Optional hand edits in config.json:

  • "ai": { "apiKeyEnv": "NAME" } reads the key from an environment variable instead.
  • "ai": { "authHeader": "api-key" } sends the key in a header of that name instead of Authorization: Bearer.
  • "ai": { "headers": { "name": "value" } } adds extra headers.
  • "ai": { "query": "api-version=2024-10-21" } adds a query string (for Azure-style services).

If the network inspects HTTPS

A firewall that replaces certificates stops the server reaching cloud AI providers. The test fails with "Certificate not trusted". Save the firewall's CA certificate (PEM format) as ca.pem in the DeskBoard folder and restart the server. start-server.cmd picks it up automatically. Local models are not affected.

Where scripts and chats are collected from

Every 5 minutes (and when you click Rescan) the server scans for scripts and Claude chats.

  • Script folders: %USERPROFILE%\Development, every project folder on the board, and every folder a Claude chat ran in. It skips node_modules, .git, venv, dist, build, .claude and similar. It stops at 4,000 files or 6 folders deep.
  • Script types: .ps1, .psm1, .py, .bat, .cmd, .sh, .vbs.
  • Chats: the transcripts Claude Desktop and Claude Code keep in %USERPROFILE%\.claude\projects.

To change the folders or file types, add this to config.json (relative folders are relative to your user folder):

{
  "collect": {
    "scriptRoots": ["Development", "C:\\Scripts"],
    "extensions": [".ps1", ".py", ".bat"]
  }
}

Backup and restore

data.json is the whole board. The server protects it automatically:

  • Before the first change each day it copies the board to backups\data-YYYY-MM-DD.json. The last 14 days are kept.
  • If data.json is ever unreadable (for example a hand edit left a typo), the damaged file is saved as backups\data-unreadable-<date-time>.json before anything overwrites it.

To restore: close the board window, stop the server, copy the backup you want over data.json, then start the server again.

Also worth keeping a copy of: config.json (AI connection, contains any key), launchers\ (start scripts) and docs\. collected.json and requests.json are rebuilt automatically.

If you hand-edit data.json, stop the server first and keep the file valid JSON. A typo makes the board look empty, and the next change you make saves over the file (your old copy is kept in backups\).

Removing Desk Board

  1. Stop the server (command above).
  2. Delete the Desk Board shortcut from the desktop.
  3. Run startup-remove.cmd if you installed start at sign-in.
  4. Delete the DeskBoard folder. Keep data.json first if you want the board.

Desk Board stores nothing elsewhere, except its window preferences (see the reference).

Desk Board: reference

Last updated 2026-10-15. For day-to-day use see the user guide; for fixes see setup and troubleshooting.

Architecture

A single Node.js server (server.js, no dependencies) listens on 127.0.0.1 port 4173. It serves the page (index.html), stores the board in data.json, scans for scripts and chats, relays AI requests, and starts or opens things on request. The page talks to it with fetch and checks for changes every few seconds. A second small program, mcp-server.js, lets Claude sessions read and update the same files.

Edge window (index.html)  <--->  server.js  <--->  data.json, config.json, collected.json, requests.json
                                    |  
                                    +--> AI providers (only when you click an AI button)
                                    +--> Explorer, VS Code, launcher scripts (only when you click a button)
mcp-server.js (Claude sessions)  <--->  the same JSON files

Data format (data.json)

One JSON object. Each key is a list. Every item has an id (text, unique within its list) and most have createdAt (milliseconds since 1970).

ListFields
todostitle, due (YYYY-MM-DD or null), priority (high, normal, low), project (project id or null), repeat (empty, daily, weekdays, weekly, monthly), link, done, doneAt
projectsname, status (active, waiting, blocked, unsorted, done), next, path (relative to the user folder, or absolute), notes, updatedAt
attentiontitle, note, severity (high, normal), source, url, resolved, resolvedAt
linkstitle, url, kind (artifact, doc, other), note, updatedAt (YYYY-MM-DD)
checkliststitle, project, items (a list of { id, text, done }), source, updatedAt
appsname, description, start, url, port, project
chatmapid (chat id), project (project id, or empty for none): your manual project choice for a chat
reviewsdate, text

Writes are checked: the page sends the file's last-modified time with each save, and the server refuses a save made on stale data (HTTP 409). The page then reloads and asks you to redo your change.

Settings (config.json)

{
  "ai": {
    "provider": "openai | anthropic | claude-code | desktop",
    "baseUrl": "https://api.example.com/v1",
    "model": "model-name",
    "apiKey": "saved by the Connect AI dialog",
    "verified": true
  },
  "collect": { "scriptRoots": ["Development"], "extensions": [".ps1", ".py"] }
}

Optional ai keys: apiKeyEnv, authHeader, headers, query (see setup and troubleshooting). The verified flag is set by a passing test and cleared when the settings change. Claude Desktop needs no test.

How each provider is called:

Security model

  • The server listens on 127.0.0.1 only. Other PCs cannot reach it.
  • It rejects requests whose Host is not 127.0.0.1:4173 or localhost:4173, and any /api request without the X-Deskboard header or with a foreign Origin. A web page in another tab cannot use it.
  • The API key lives only in config.json. The page can see whether a key exists, never the key.
  • Opening and starting are limited to what the board already holds. POST /api/open works on a project id, a script found by the scan, a task's link, or an app id, never on a path the page supplies. Starting an app requires a start script that exists, is a .cmd, .bat, .ps1, .vbs or .exe inside the user folder, and has no shell characters in its path.
  • The Claude Code provider runs with no tools and no session saved.
  • Data stays on this PC. The only outbound traffic is to the AI provider you chose, when you click an AI button, plus Google Fonts for the typeface.
  • Anything that can edit data.json can add an app whose script you may later start. Only click Start on apps you recognise.

How collection works

Scripts. The collector walks the script folders (see setup) and also adds every script that Claude wrote with its file tool, found in the chat transcripts, except those in temporary or work-tree folders. For each file it records the language, size, modified date, project (the project whose folder contains it, longest match) and a one-line description from the first comment:

TypeDescription taken from
PowerShell.SYNOPSIS, else the first # comment, else the first line of a <# #> block
PythonThe module docstring, else the first # comment
BatchThe first REM or :: line
ShellThe first # comment after the first line
VBScriptThe first ' comment

Chats. Each file in %USERPROFILE%\.claude\projects\*\*.jsonl is one chat. The title is the chat's name, else the last message. The project comes from the folder the chat ran in. Chats with no folder (the scratch workspace) show as No folder. Only the title, last message snippet, message count and times are used; chat content is never copied. Results are cached by file size and modified time, so rescans are quick.

What counts as "this week"

See the table in the user guide. In short: tasks are current when overdue, due within 7 days, high priority, or added this week; the other panels use the last change or last message date; needs attention is always shown; searching or focusing a project overrides the 7-day view.

Preferences stored in the browser

The window remembers its tab, the 7-day or Everything choice, the focused project, and collapsed panels in the browser's local storage under the key deskboard.prefs. Clearing the browser's site data resets them. They are not part of the board.

Source code and releases

The code is in two private GitHub repositories with the same history: LCMS-Foundation/DeskBoard (remote lcms) and 78tacos/DeskBoard (remote origin). Versions are tagged vX.Y.Z and published as releases with a zip attached. CHANGELOG.md lists what changed in each version.

Not in the repository, by design: data.json, config.json, requests.json, collected.json, backups\, launchers\logs\ and ca.pem (see .gitignore).

To make a release:

  1. Update CHANGELOG.md and the affected articles in docs\, then run node docs\build-docs.js.
  2. Commit, then tag: git tag -a vX.Y.Z -m "Desk Board X.Y.Z".
  3. Push the branch and the tag to both remotes: git push origin main --tags and git push lcms main --tags.
  4. Make the zip: git archive --format=zip --prefix=DeskBoard/ -o DeskBoard-vX.Y.Z.zip vX.Y.Z.
  5. Create the release in each repository with gh release create vX.Y.Z DeskBoard-vX.Y.Z.zip --title "Desk Board X.Y.Z" --notes-file <notes>, adding -R LCMS-Foundation/DeskBoard or -R 78tacos/DeskBoard.

Not included

  • Live mail, calendar or ticket panels. Anything a Claude session reads from a connected service can be added to the board as a needs-attention item or a task.
  • Chats from claude.ai in a browser.
  • A Stop button for apps.
  • Use by more than one person or from more than one PC.

Using Desk Board with Claude

Last updated 2026-10-15. Desk Board and Claude work together in four ways. This article covers what each does, how to set it up, and the rules Claude sessions follow.

The four ways Claude is involved

WhatHow it worksSetup
Claude sessions update the boardA session in the DeskBoard folder can read and change tasks, projects, checklists, links, attention items and apps through the deskboard toolsApprove the deskboard server when a session asks
Claude Desktop answers the AI buttonsThe board queues each AI request and a Claude session answers itConnect AI, then choose Claude Desktop
Claude Code answers the AI buttonsThe server runs Claude Code in the background, with no toolsConnect AI, choose Claude Code, sign in once
Chats and scripts are collectedThe board reads the chat history and the scripts Claude wrote on this PCNothing to set up

The first two work without an API key. Neither sends your board anywhere except through your own Claude sessions.

Claude sessions updating the board

.mcp.json in the DeskBoard folder registers a small program, mcp-server.js, as an MCP server named deskboard. When you open a Claude session in the DeskBoard folder, it asks you to approve the server once. After that the session has these tools:

ToolWhat it does
deskboard_getReads the board: open tasks, projects, open attention items, links, checklists, apps, counts of collected scripts and chats, and pending AI requests. Sessions call this first.
deskboard_addAdds a task, project, attention item, link, checklist or app
deskboard_updateChanges fields on an item by id
deskboard_deleteDeletes an item by id. Sessions only do this when you ask.
deskboard_collectedLists the collected scripts or chats
deskboard_requestsLists AI requests waiting for an answer
deskboard_answerAnswers one request

Things you can say in a session:

  • "Add a task to call the vendor on Friday, high priority."
  • "Put the steps from this chat on the Sorto project as a checklist."
  • "Register this app in the Launcher." (The session writes a start script in launchers\ and adds the app.)
  • "Add the artifact you just made to Desk Board."

The board shows changes within a few seconds. Anything that touches an item should refresh its updatedAt, which keeps checklists, projects and links in the 7-day view.

If the tools are not available in a session (for example the session started before the server was registered), Claude falls back to Node's store.js, which writes data.json the same way.

What Claude sessions are told to do

CLAUDE.md in the folder is read by every session in it. Its main rules:

  • Call deskboard_get first. Delete only when asked.
  • When a chat produces a list of steps or things to check for a project, add it as a checklist on that project and say so.
  • When something is built that the user runs locally, put a start script in launchers\ (one command, output to launchers\logs, a rem line saying what it does) and register it as an app with its address.
  • Add artifacts and documents as links.
  • Add things the user must decide as needs-attention items with the source Claude.
  • Never read or print config.json, and never copy an API key anywhere.
  • Keep the server, collector and MCP server free of dependencies, and never expose the server beyond 127.0.0.1.

Claude Desktop as the AI

Click Connect AI, choose Claude Desktop (a session answers), and click Use Claude Desktop. No key and no test are needed.

When you click an AI button the board shows "Waiting for Claude Desktop". To answer:

  1. Open a Claude session in the DeskBoard folder.
  2. Say handle Desk Board requests.
  3. The session reads the waiting requests with deskboard_requests, writes each answer in the format the request asks for (plain text, or only a JSON list for Paste to tasks), and sends it with deskboard_answer.
  4. The board shows the answer.

A request waits up to 15 minutes, then expires with a message. The Connect AI dialog shows when a session last used the board.

This needs a Claude session to be open. If you want answers without one, use Claude Code or an API provider instead.

Claude Code as the AI

Choose Claude Code on this PC (needs one-time sign-in). The server finds claude.exe in your Claude Desktop install (%APPDATA%\Claude\claude-code) and runs it in the background with no tools and no saved session. It uses your Claude plan.

Claude Code has its own sign-in, separate from the desktop app. Run the sign-in command shown in the dialog once, in a terminal, then click Save and test. Until then the test says Claude Code is not signed in.

What Claude can see

  • Chats: the chat history Claude Desktop and Claude Code keep on this PC. The board uses titles, a snippet of your last message, message counts and times. It does not copy chat content.
  • Scripts: files on this PC, plus every script Claude wrote with its file tool in those chats.
  • Not visible: claude.ai chats in a web browser, and anything stored only in Claude's cloud.

Sending data to an AI provider

Only the AI buttons send anything, and only to the provider you connected. The exact contents are listed in the AI buttons table in the user guide. With Claude Desktop, the content goes to your Claude session. With Claude Code or an API provider, it goes to that service.
